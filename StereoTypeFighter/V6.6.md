# StereoType Fighter V6.6

## Release focus
- Normalize character presentation across the full roster.
- Improve rendering speed / responsiveness.
- Add a browser-based Audio / Settings admin page.
- Allow per-stage music and per-character action sound assignment.
- Add sync controls so sounds can be aligned to animation timing.

## What changed
### Roster and presentation
- Full 20-character roster consolidated into `tools/roster-v66.json`.
- All fighters now use a common normalized runtime sizing model.
- All 20 fighters now use the same normalized portrait-puppet runtime renderer for consistent scale, silhouette, anchoring and fast loading.
- Existing HD atlas metadata remains available for future art upgrades without blocking the V6.6 runtime.

### Performance
- Portrait-first loading on the select screen.
- Lazy fighter asset loading: detailed animation data only loads for selected fighters.
- Lightweight fixed-step arena loop with real-time FPS readout.
- Reduced up-front memory pressure versus loading every fighter animation sheet at startup.

### Audio / admin
- New `admin.html` page.
- Upload and replace audio files in-browser using IndexedDB.
- Assign:
  - stage background music,
  - per-fighter action SFX,
  - UI sounds.
- Per-slot controls:
  - enabled toggle,
  - volume,
  - sync offset,
  - stage music loop toggle.
- Waveform preview and animation preview for timing alignment.

## File overview
- `index.html` — main game page
- `app-v66.js` – selection UI + game bootstrap
- `arena-v66.js` – match loop and combat logic
- `sprites-v66.js` – normalized portrait-puppet renderer with lazy portrait loading
- `sound-v66.js` – runtime sound system and defaults
- `audio-store-v66.js` – IndexedDB persistence layer
- `admin.html` / `admin-v66.js` — audio/settings admin UI 
- `ui-v66.css` – shared styling

## Notes
- Audio uploads are local to the browser profile until exported or manually committed into a repo.
- This package is prepared as a next-version release bundle for GitHub, but pushing to a remote repository still requires GitHub access/credentials from the execution environment.
